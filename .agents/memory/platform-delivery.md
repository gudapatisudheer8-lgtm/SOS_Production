Admin and accountant need both web and mobile access. Partner is intended as a mobile application, but initially must work as a mobile web application. Complete browser development before preparing native mobile versions of all dashboards.

**Why:** The user explicitly specified these role/platform requirements and the web-first delivery sequence.

**How to apply:** Make admin and accountant interfaces usable on desktop and mobile browsers, and make partner interfaces mobile-first. Preserve sector-specific interfaces for both accountant and partner. Native releases remain a later delivery milestone, not a claim that a browser-only implementation is automatically a finished mobile app.
